# Minutes 视觉系统（2026-11-04 重设计）

> 一句话：**判断这场会议记录是否可信，并快速定位到某段发言。**

界面服务的是"核对"，不是"被欣赏"。所以这套视觉语言的目标是：安静、有材质、状态一眼可辨。

---

## 一、为什么之前是"灰秃秃"

不是不合规 —— 机械自检（`ui-audit.py`）当时就打 9.90/10。问题是**三处具体的、可量化的缺陷**：

| # | 缺陷 | 证据 | 后果 |
|---|---|---|---|
| 1 | **白底白卡** | 宿主亮色模式 `--dsw-alias-bg-base` / `-layer-1/2/3` 全部 = 白色（实测自 `dsh-client-ui-theme/lib/client.js` 的 design-platform.css）。插件自己又用 `color-mix(bg-base 97%, label-primary 3%)` 做卡片 | 卡片与画布明度差约 1%，只有 11% 灰发丝线，**零深度**。整页读起来是一块灰白的糊 |
| 2 | **强调色被当文字色用** | `--mvm-accent-line` = 强调色 42% alpha，被 `.mvm-detail-tab.is-active` 直接用作 `color` | 白底对比度约 **1.6:1**，硬性无障碍缺陷。旧强调色 `#9a6d1f` 本身在卡片上也只有 4.31:1 |
| 3 | **小字发灰** | 次要文字全部走宿主 `--dsw-alias-label-secondary/tertiary`；tertiary 亮色 `#81858c` = **3.71:1** | 12px 的元信息、时间戳、说话人标签集体"洗白" |

另外，**44 个类在样式表里有规则但没有任何渲染函数会发出**，其中包括 `.mvm-detail-rail`、`.mvm-library-item`、`.mvm-segment*`、`.mvm-template-*`。这些是旧设计的残留，等于同一个文件里塞了两套互相冲突的视觉语言。

## 二、方案：冷石墨 + 黄铜

情绪主张：**冷石墨之上的一点黄铜 —— 工具退到内容后面。**

选色相的三个旋钮：VARIANCE 3 / MOTION 2 / DENSITY 6（工作档，比 Reader 密）。

### 2.1 表面：三层，全部由宿主 token 推导

| 角色 | 亮色 | 暗色 | 推导 |
|---|---|---|---|
| 画布 canvas | base 混 5% 墨色 | `--dsw-alias-bg-base` | 亮色宿主没有层级，自己压暗一档 |
| 卡片 card | `--dsw-alias-bg-base` | `--dsw-alias-bg-layer-1` | 亮色是白，暗色借用宿主 ramp |
| 浮层 overlay | `--dsw-alias-bg-base` | `--dsw-alias-bg-layer-2` | 亮色靠阴影抬升 |
| 内嵌槽 sunken | base 混 10% 墨色 | `--dsw-alias-bg-base` | 承载输入框、列表行，**不新增层级** |

相邻明度差落在 **3–5%** 区间（亮色画布 95.3% → 卡片 100%，暗色 8.5% → 15.4% → 18.0%），既读得出层级，又不到"显脏"的 12%。所有取值都是 `color-mix()` 公式，宿主换主题时插件跟着换。

### 2.2 强调色：一个值，三种用途

黄铜 `#8A5E0C`（亮）/ `#E3A82B`（暗）。

关键设计约束：**同一个 accent 值在两种主题、每一种表面上都 ≥4.5:1**。

| | 卡片 | 画布 | 内嵌槽 | 反色文字压上去 |
|---|---|---|---|---|
| 亮 `#8A5E0C` | 5.70 | 5.13 | 4.61 | 5.70（白字） |
| 暗 `#E3A82B` | 7.40 | 8.60 | 8.60 | 8.60（深字） |

所以它可以同时当**填充、描边和文字**用 —— 不需要第二套"文字专用色"，也就不会出现描边色和文字色打架的老问题。

高彩度的 `--mvm-gold`（`#D9A441` / `#F0C561`）是**图形档**，只允许落在深色仪表条上，永远不上纸面（白底只有 2.25:1）。

### 2.3 文字：三档，自己定档

宿主的 label-tertiary 用不了，所以插件自己混：

| 档 | 推导 | 亮色 | 卡片上 | 内嵌槽上 |
|---|---|---|---|---|
| ink | `--dsw-alias-label-primary` | `#0f1115` | 18.9:1 | — |
| ink-2 | 墨色 76% + 底色 24% | `#505154` | 7.94 | 6.42 |
| ink-3 | 墨色 66% + 底色 34% | `#616265` | 6.10 | 4.94 |

同一套公式在暗色下自动成立：ink-2 `#bbbcbd`（卡片 8.26）、ink-3 `#abacad`（浮层 6.13）。

### 2.4 语义色：三件套，不向品牌靠拢

`fill / ink / soft` 三件。宿主的状态色在亮色下不够用（error-primary `#ec1313` 只有 4.0:1），所以插件自建。

| | fill | ink | soft 上的 ink |
|---|---|---|---|
| ok | `#158048` | `#12703C` | 5.32 |
| warn | `#A85F08` | `#8A560A` | 5.35 |
| err | `#C4362E` | `#A92C25` | 5.74 |
| info | `#235FBE` | `#1D559E` | 6.25 |

状态永远是**颜色 + 文字 + 形状**三通道，不靠颜色单独表意。

### 2.5 阴影：染暗，不染字

暗色模式下宿主的 label-primary 是近白色，拿它调阴影会得到一层白雾。所以阴影一律从一个永远比纸面暗的 `--mvm-shade` 来（亮色 = label-primary，暗色 = bg-base）。

卡片 = 发丝线 + 一层极轻的阴影（材质感）；浮层 = 两层更重的阴影。控件（按钮、输入、标签页）永远不浮。

### 2.6 签名装置：capture rail

一条黄铜线：页头下方左侧 24% 实色、其余渐隐。实时录音时由深色仪表条上的琥珀色波带接续 —— 同一个装置的两种形态。

它只出现在一个地方。第二个签名装置会抵消第一个。

---
- **token 层**：整块重写，全部改为宿主 token 推导；样式表里不再有任何十六进制或 rgba 字面量（插件自身的 `tests/client-contract.test.mjs` 对此有硬约束）。
- **文字层**：89 处 `label-secondary`、1 处 `label-tertiary`、47 处 `label-primary` 全部换成插件自己的三档；`--mvm-accent-line` 当文字色用的地方改成 accent-ink。
- **表面层**：64 处 `surface-2` 按角色拆成 sunken / hover / accent-soft；斑马纹改成发丝线。
- **深度层**：卡片重新获得阴影，悬停有 1–2px 抬升。
- **语义层**：11 处 success / 12 处 error / 9 处 warn 换成自建三件套。
- **签名层**：页头 capture rail；实时波带改成深色仪表条 + 琥珀条，静止时不再播放呼吸动画（动效只服务状态）。
- **空态**：加了图标标记，不再是一堵灰字。
- **行长**：逐字稿正文限到 52em，长段落不再横跨整屏。

### 3.0b Live 页面：量出来的三个问题与修法

第一轮截图看起来"还行"，但**量一下**才发现三处硬伤（`uiux-demos/minutes-harness/audit-layout.mjs` 量的是活的 DOM，不是目测）：

| 问题 | 量到的数 | 根因 | 修法 |
|---|---|---|---|
| 两个面板塌成内容高度，**下面 356px 全是空的**（占视口 43%） | studio-grid h=268 / workspace h=817，填充率 **0.33** | `.mvm-live-workspace` 是 block 容器，所以里面的 `flex:1` 是空话；`.mvm-studio-grid` 又写了 `align-items:start`，栅格列直接塌成内容高；`.mvm-studio-column` 是 block，高度分不到事件列表 | workspace 改成 flex 列 → container `flex:1` → grid `align-items:stretch;flex:1` → column 改成 flex 列 → 事件列表 `flex:1;min-height:0` 接管剩余高度并自己滚动 |
| 电平表静止时是一个**纯黑的空盒子** | 静止刻度只有 **1.7px** 高、金色 32% alpha | 静止基线 `scaleY(.08)` 太低，刻度在黑底上等于不存在 | 静止基线提到 `scaleY(.18)`、金色 58% alpha、基线规则 45% —— 读起来是一把闲置的刻度尺，而不是坏掉的播放条 |
| 电平表浮在整行中间，两边都是空的；标签还排在图形**右边** | ribbon x=813，两侧各空 300+px | 一行三个子元素用 `space-between`，中间那个就被推到中间；`LiveRibbon` 里标签写在轨道之后 | 行改成左对齐堆积，`.mvm-ribbon{margin-left:auto}` 把仪表推到右侧和 Track filter 成一组；标签移到轨道**之前**，读作"Live level ▁▂▃" |

顺带：面板变高后，空状态用 `margin:auto` 在面板里**居中**，而不是黏在顶上。

### 3.0c 电平表：那块黑板是错的

上面三条修完，Ethan 指着电平表说"这个样式也太丑了"。他说得对，而且指出的正是我自己的设计错误。

**我原来为什么那么做**：想让高彩度的金 `#D9A441` 有地方出现（它在白底只有 2.25:1，放不上纸面），于是给电平表造了一块深色仪表板。结果那块 **近黑的矩形成了整个浅色页面上最深的东西**，里面的刻度只有 1.7px 高、32% alpha —— 看上去不是仪表，是一个**坏掉的播放条**。

**重新设计：电平表不再有自己的材质。**
- 去掉那块板。电平表由页面自己的材料构成：**黄铜刻度 + 一根发丝基线**，没有容器。
- 静止时是一排 34% 黄铜的短刻度（暖砂色，安静但认得出是黄铜，不再是一段灰虚线）；录音时刻度变成实心黄铜、按真实振幅起伏。
- 刻度从**基线**往上长（`transform-origin:bottom`），这是电平表的读法，不是从中间长。
- 宽度收到 110px、刻度 2px、间距 2px，28 个采样点更密，读起来像一段波形历史而不是装饰。
- 动效交给刻度（120ms 跟随真实电平），基线不再"呼吸"—— 呼吸是装饰，振幅是数据。

`--mvm-console` / `--mvm-console-edge` / `--mvm-gold` 三个 token 随之删除。**高彩度的金本来就不该单独存在**：强调色只有一个值（黄铜），它自己就够亮。

教训记在这里：**"给某个组件造一块专属材质"是很容易犯的错。** 家族材料只有一套，组件应该从里面取，而不是另起炉灶 —— 另起的那个就是页面上最扎眼的东西。

修完再量：studio-grid h=520 / workspace h=917，**剩余空白 104px = 悬浮控制条的高度**（本来就是给它留的），填充率 0.64 —— 从"浪费 43% 视口"变成"一点不浪费"。

同一套量法扫了另外两页，确认没有同类问题：
- **详情页**：`.mvm-detail-tab-content` 自己滚动（scrollHeight 4932 / clientHeight 554），逐字稿在正确的容器里滚 ✓
- **会议库**：内容只有一场会议，空白是内容长度决定的，不是布局缺陷（`.mvm-workspace` 超过视口时才会滚动）✓

### 3.0d 观点树：照着目标图重做

Ethan 给了一张目标图（暗色、深色节点块、彩色分支、卡片带同色底与描边），说"你应该做到截图2中的效果"。对着目标图量出货��实现的差距，一共五条：

| | 原来 | 目标 | 改法 |
|---|---|---|---|
| 分支节点 | `hue 14%` 的淡染 + 同色字 → 一片糊 | **实心深色块 + 浅色字**，每条分支一个焦点 | 改用语义色的 **fill 档**（`--mvm-ok-fill` 等），文字用 `--mvm-on-semantic` |
| 树脊与连线 | `hue 42%` 混发丝线 → 几乎看不见 | 明显的彩色竖线 + 圆角拐弯连进卡片 | 提到 55–58%，并把直连改成**圆角肘弯**（左竖 + 下横 + 左下圆角） |
| 卡片底色 | `hue 8%` → 几乎等于白 | 明显的同色底 | 提到 13%，描边 38% |
| 卡片标题 | 13px / 同色字，糊在正文里 | **15px / 600 / 明确的分支色** | 提到 15px，用分支的 ink 档 |
| 卡片末尾那行小字 | 一律用 warning 色 | 用**分支自己的色** | 改成 `mind-ink` 混 82% 表面色 |

最后一条不只是审美：**每条分支都是 amber warning，而分支本身已经是五种色** —— 那一行琥珀色既打断了分支身份，也让整页多出第六种色相。现在每个分支从头到尾只有一种色。

另外给每条分支补了第三档 `--mind-fill`（节点块的实心底色）。语义色本来就是三件套（fill / ink / soft），之前只用了 ink 和 soft，fill 一直空着。

#### 树的几何（量过的，不是估的）

Ethan 明确要求"**不要左侧一条贯穿到底的长竖线**"，层级靠缩进表达。所以把 `.mvm-mindmap-group::before`（那条竖线）**整条删掉**，改成每个节点自己画一小段连线：

| | 位置（组内坐标） |
|---|---|
| 分组标题（���级） | x=0，实心深色块 + 加粗浅色字 |
| 子观点卡片（二级） | x=34，缩进一级 |
| 连线列 | x=0（分组标题的左边缘），父节点自己的短竖桩 + 每个子节点各自的短折线 |

- 父节点左边缘垂下一段 14px 的短桩。
- 每个子节点画**一个圆角肘弯**：从父节点那一列下来，用 16px 圆角转向，**正好落在卡片标题的基线上**紧贴卡片左边缘。

第一版是「一条 34px 横线 + 一段 12px 竖线」拼的 L 形，两段各自独立 —— 于是父节点的短桩和子节点的折线**之间断了一截**，看上去像两个不相干的记号。改成**一个 34×34 的方框，只画左边框和下边框、左下角 16px 圆角**之后，父到子是一条**连续的曲线**，没有断口。

这个形状用一次 `border-left` + `border-bottom` + `border-radius` 就画出来了，不需要 SVG。

这一步是量出来的：第一版把 `padding-left:30px` 加在 group 上，结果**标题和子卡片缩进量完全相同**（都落在 x=30），等于没有层级。DOM 读回来 `theme.x=450 / branch.x=450` 才看出问题，改成标题 `margin-left:-34px`、group `padding-left:34px` 才是 x=0 / x=34。

### 3.0e 观点树：第二次重做（色相预算与信息权重）

3.0d 之后 Ethan 又提了一次"这个脑图的 UIUX 重新设计下"。这次不是照着目标图对形，而是拿五维标尺审出来的四个硬伤：

| | 问题 | 为什么是问题 | 改法 |
|---|---|---|---|
| 色相预算 | `tone-0..4` 轮换 info / ok / warn / err / accent | 一屏出现五个色相族，且把**语义色当装饰**用：主题 1 是蓝色不代表任何含义，而红色被拿去区分主题，真正的风险反倒没有色相可用 | 结构只用黄铜一族；语义色只在**真的是风险**的那一块出现 |
| 信息权重 | stance 14px/600，detail 13px 用正文墨色，risk 12px 最浅 | 评审里最该被看到的是风险，它却是卡片里最轻的一行，还没有任何标签说明"这是风险" | 风险单独成块：`风险` 标签 + 三角图标 + 暖色左边线 + 13px 正文 |
| 可扫读性 | 只有主题胶囊 + 卡片，没有"这个议题讨论到哪"的信息 | 要判断哪些议题有结论、哪些还悬着，必须把每张卡读完 | 主题行加序号令牌和「N 个观点 · M 项风险」统计 |
| 装饰压信息 | 卡片是 13% 语义色淡染 + 同色描边 + 实心色胶囊 | 最响的是标签，不是内容 | 卡片回到白底发丝线 + 卡片阴影；主题从实心胶囊改成墨色标题 + 黄铜序号令牌 |

同时修掉一个数据契约错误：旧 fallback 把 `topics[].decisions`（已达成的结论）塞进 `risk` 槽位，于是一串结论被画成了警告；现在 topics 走 `decisions` 字段单独成列表，`stance` 也不再是硬编码的英文 `'Summary'`。

**第三轮：连线全部去掉。** Ethan 看完之后说"不要前面的线条了"。于是把主题短桩和每个节点的圆角拐弯一起删掉，结构改由**三条重复的对齐轴**承担：

| 轴 | 位置 | 承担什么 |
|---|---|---|
| 序号列 | x=0 | 每组一个黄铜令牌（01/02/03），是这一组的锚点 |
| 主题列 | x=36 | 主题标题、以及它下面所有卡片的左边缘，同一条线 |
| 统计列 | 右对齐 | 「N 个观点 · M 项风险」贴住卡片右边缘 |

这三条轴在每一组重复，跨组逐行对齐，比连线更硬地切分页面；而且只有一张卡片的组不会留下悬空的线头。没有线之后，主题标题必须自己扛住分组，所以从 14px 提到 **16px/600**，形成 16（主题）→ 14（论点）→ 13（论据/风险）→ 12（元信息）四级字阶。

**踩到的坑**：第一版我加了一条贯穿整棵树的连续竖脊——看起来更"像树"，但 3.0d 里记着 Ethan 明确要求过**不要左侧贯穿到底的长竖线**，层级靠缩进表达。已改回"主题令牌垂一小段短桩 + 每个节点自己的 24px 圆角拐弯"，并把这条写成了测试（`tests/viewpoint-tree-redesign.test.mjs` 里断言 `children::before` / `group::before` 不存在）。

**量过的数**：8 组文字/背景组合在亮暗两套主题下逐一测对比度，最低 5.27:1（亮色序号令牌），最高 17.76:1；`ui-audit.py` 对渲染件 9.90/10 PASS。序号令牌一开始用 `--mvm-accent-ink` 只有 4.34:1 不合格，改成 `--mvm-accent-strong` 后 5.27:1。

**验证**：重跑 `build-css.mjs` 让 harness 用出货样式表 + 真实会议记录（`realtime-1793864825450-6dc02d90`）渲染，亮暗两套截图；插件全量测试 297 条 296 通过 0 失败 1 跳过（跳过项需 `--expose-gc`）。

### 3.0f 逐字稿：字号和行距收回来

### 3.0g 会议库列表：那条横滚动条其实藏着一个功能 bug

Ethan 指着列表视图底下一条灰条问"这个滚动条是什么鬼"。量出来它不只是难看：

| | 值 |
|---|---|
| 表格容器 | 1073px 可用宽 |
| 行内容 `min-width` | **1180px** |
| 结果 | 横向溢出 107px → **出现横向滚动条**，而**最后一列（删除按钮）被顶出可视区** |

也就是说列表视图里**根本点不到删除**。截图上那句被拦腰截断的摘要也是同一原因：行被裁掉了，不是文字被省略。

修法是让表**装得下**，而不是把滚动条藏起来：

| | 原来 | 现在 |
|---|---|---|
| 列宽 | 32 / 260 / 150 / 90 / 120 / 110 / 90 / 40，间距 14 | 28 / 200 / 142 / 76 / 92 / 88 / 68 / 36，间距 10 |
| `min-width` | 1180px | **828px** |
| 内边距 | 14px 16px | 12px 14px |

828px = 固定列 530 + 标题最小 200 + 间距 70 + 内边距 28 —— 刚好等于内容需要宽度，**表格不会再溢出自己的最小宽度**。

同时给行加了 `flex:none`：表格是 flex 列容器，行会被压扁；面板一矮，行的内容就被裁掉。

`overflow-x:auto` 保留 —— 面板窄到 828px 以下时仍然需要横滚，但那个宽度已经比任何正常窗口都窄。

**测试也一起改了**：原来那条断言写死了 `min-width:1\d{3}px`（1180 的形状）。现在改成断言**不变量** —— 最小宽度必须 ≥ 固定列 + 标题最小 + 间距 + 内边距，且必须 < 900px（装得进最窄的面板）。这样以后再改列宽，这条测试会自己抓住"内容装不下"或"最小宽度失控"。

### 3.1 顺手修掉的两个真 bug

- **`Icon` 丢弃 className**：`Icon({name, size, fill})` 从不接收也不应用 `className`，所以 `.mvm-voicebook-group svg.is-open`（分组展开时那个 chevron 旋转）**永远不会生效** —— 声音库展开箭头一直是不转的。`Icon` 现在接收并应用 `className`。
- **模型徽章缺第三态**：`.mvm-model-badge` 有 `is-active` / `is-ready`，唯独 `is-missing`（未下载）没有规则，落回普通徽章样式，看不出是"还没下载"。补了一条虚线描边的中性态。

### 3.2 删掉的死 CSS

样式表里曾经并存两代视觉语言：44 个类有规则但任何渲染函数都不会发出（`.mvm-detail-rail`、`.mvm-detail-body`、`.mvm-library-item`、`.mvm-library-grid`、`.mvm-segment*`、`.mvm-template-*`、`.mvm-chat-chip`、`.mvm-voice-dot` …）。

删法是**可证伪的**，不是靠眼力：

1. 把样式表从源码里切掉，剩下的每一个字都算"标记或逻辑"；
2. 一个类只有在标记里**完全没出现过**才算死类（整词匹配，不是前缀匹配）；
3. 动态拼出来的类名要单独处理（`tone-${index % 5}`、`is-${role}`）—— 第一版脚本漏了这一步，误杀了 `tone-0..4`、`is-assistant`、`is-flag`，被断言拦下后重写；
4. 复合选择器里**任何一个**祖先类死了，整条复合就永远不会匹配（`.mvm-library-grid .mvm-library-row` 里 grid 没渲染过，行也就不会出现在 grid 里）；
5. `:not(...)` 里的类是"排除项"不是"必需项"，不算死因；
6. 最后加一道保险：**所有活着的选择器组，改写前后必须一一对应**，少一个就中止写盘。

改写过程中脚本真的踩了两次坑，都被这道保险或断言抓住：一次是 `@media` 块内递归时偏移量没加基准，把 CSS 切坏、页面掉样式；一次是把纯插值 token 当成通配符，导致所有类都被判成活的。两次都是先还原、再修脚本、再重跑。

### 3.0h 本地服务自启动：一个从没生效过的开关

Ethan 的要求是"重启 DSH 时 ASR 服务默认自启动，包括翻译模型"。查下去发现不是没实现，是**实现从来没跑到**：

```js
// 改之前
ctx.provide('minutes', service);
if (service.config.asrAutoStart) void asrAdmin.start();   // ← 此刻 config 还是 DEFAULTS
```

`service.config` 在构造时只有 `DEFAULTS`，`settings.json` 要等第一次 `ensureSettings()` 才读进来。`DEFAULTS.asrAutoStart` 是 `false`，所以这一行**每一次都是 false**，用户勾了也白勾。真机证据：16:01 时 8010 端口没有任何监听。

改法是先读设置再判断，并把翻译模型也纳进来（`llm-admin.js`）：

| 关注点 | 做法 |
|---|---|
| 顺序 | `await service.ensureSettings()` → 再判断两个开关 |
| 只启动该启动的 | 只加载设置里 `provider === 'lmstudio'` 的**主**模型；云端 provider 一个进程都不碰；备用模型按需加载，不在启动时预载 |
| 幂等 | ASR 先探活，在跑就不重启；模型先 `lms ps`，驻留就不 load |
| 就绪的判据 | `lms ps` 的**驻留**状态，不是 `/v1/models` —— 后者列出磁盘上有的模型，`qwen3.5-9b-mtp` 明明没加载也会被列出来 |
| 失败面 | 全部 catch，只记日志，绝不阻塞宿主启动 |
| 边界 | 启动钩子是显式选项 `autoStartLocalServices`，默认跟随平台：真宿主开、`NODE_TEST_CONTEXT` 环境的测试关 |

**踩到的两个坑**：

1. 第一版没有这个边界，全量测试里 20 多个用例各自 `apply()` 一次，于是真的拉起了 20 多次 python 和 LM Studio，还按 `DEFAULTS`（本地 LLM）把 `qwen3.5-9b-mtp` 加载了两份，测试挂了 53 条。

### 3.0i 字幕不出：一个被塞进实时列表的精修模型

Ethan 开会十分钟没等到字幕。查下来不是网络、不是翻译，是**配置把一个精修模型设成了实时后端**：

| 同一段真实 3 秒音频（用户自己的录音） | 耗时 | 输出 |
|---|---|---|
| SenseVoice（快后端） | **0.52s** | 可以啊，那很简单，只要有录音，只要有。 |
| Fun-ASR（当时的 `asrBackend: funasr`） | **28.18s** | 可以啊，你很简单，你只要有录音，只要有。对对对对。 |

那场 89 秒的会话日志：收到 15 段音频，**只转出 2 段**，6 段被丢弃，队列峰值 5。Fun-ASR worker 日志显示每 15 秒 "Loading ckpt" 一次——它每处理一个请求就重载权重，而 3 秒一段的实时流每分钟要 40 个请求。

**真正的设计错误在配置界面**：`asrBackend` 一个下拉同时管「实时字幕」和「精修」，而 `/finalize`（精修）**永远**走 Fun-ASR、与这个下拉无关。于是这个下拉实际上只有"实时字幕"一个含义，却把精修模型也列在里面，选它 = 让整场会议没有字幕，界面上看不出区别。

改法（三层）：

| 层 | 改动 |
|---|---|
| 目录 | 每个模型加 `capability: 'live' \| 'refine' \| 'diarize'`；只有 live 可被选为字幕后端 |
| 后端 | `LIVE_BACKENDS = ['whispercpp','sensevoice']`；保存的 `funasr` 自动迁移成 `sensevoice`，并在 `asr-status` 时写回文件 |
| 界面 | 拆成两块：「实时字幕模型」（快模型单选）与「会后精修模型」（Fun-ASR 固定行 + 就绪状态 + 预热按钮），各自写明**换/删它的后果** |

另外两个连带修复：

1. **实时分段不再跑说话人分离**。服务端 `--diarize` 开着，`/v1/audio/transcriptions` 每段都跑一遍 ECAPA——而实时字幕本来不显示说话人，说话人是会后用整条音轨聚类的。现在加了一个按请求的 `diarize` 开关，实时路径传 `false`，导入音频与精修仍保留。
2. **`asr-status` 先读设置再回答**。和之前 `local-models-status` 是同一类 bug：面板可能在 `settings.json` 读进来之前就问，于是显示的是 DEFAULTS 的后端而不是你保存的那个。

**端到端验证**（把真实录音按实时速率喂进插件的完整管线）：首条字幕 **3.6s**，之后每 **3.0s** 一条，8 段全部转出、0 丢弃、队列深度始终 1。对比故障那场：15 段只出 2 段。

### 3.0k 半透明与阻塞：两个都属于「窗口没摆对自己的位置」

**半透明**：截图里浮窗后面的聊天文字透了出来。根因不是渲染，是配置——`overlayOpacity: 0.6` 被直接当成窗口的 `alphaValue`：

```swift
window.backgroundColor = NSColor(background).withAlphaComponent(appearance.opacity)
```

0.6 的窗口意味着字幕是浮在别人文字上的，读起来自然费劲。三处一起改：把保存的值设为 1；解析时把下限提到 **0.85**（再低字幕就压不住背景）；透明度到 1 时把窗口设成 `isOpaque = true`（0.999 仍然会混背景）。设置表单的下限同步到 0.85，标签也写明「低于 0.85 会看不清字幕」。

**阻塞**：结束会议原本是一条同步链——等采集收尾 → 读日志 → 落库 → 聚类 → 精修 → 生成纪要 → 全都完成后路由才返回，期间浮窗还挂着「正在整理会议纪要…」。读者看到的就是"窗口挡在那、按钮全灰"。

改法是把这条链拆成两段：

| 段 | 内容 | 何时返回 |
|---|---|---|
| 立即 | 关浮窗、返回 `{ session: stopping, meeting: { inProgress: true } }` | **3ms**（实测） |
| 后台 | 收尾、落库、聚类、精修、纪要 | 完成即写回记录 |

页面不再等：`live-stop` 一返回就切到会议库并提示「正在后台保存并生成纪要，可以先做别的事」，后台用 `live-stop-status` 轮询，记录落地就自动打开这场会议。浮窗不再承担"进度条"的角色——它是字幕窗，任务在按下结束那一刻就结束了。

**顺带修掉一个真 bug**：进程在会话目录被删掉之后继续写 checkpoint / 事件，会抛 `ENOENT` 变成未处理拒绝（后台收尾比页面活得久，这个场景现在真的会出现）。`realtime.js` 的 `_checkpoint` 与 `_emit` 现在把 ENOENT 当作"目录已经不存在"跳过。

**验证**：新增 `tests/live-stop-nonblocking.test.mjs` 四条——返回耗时上限（用一个故意慢 800ms 的 manager 来测"有没有等"）、重复点击幂等、`live-stop-status` 的状态流转、浮窗在 stop 完成前就关闭且不推任何 notice。另加实测脚本：`live-stop` 返回 **3ms**，后台落库 **+106ms**。全量 315 条 314 通过 0 失败 1 跳过；Swift 自检 54 项通过。


### 3.0l 会议库：先把「一行是什么」理清，再谈批量

旧的列表有一个 8 列的表，但**第一列表头写着 All、单元格却是空的**（`librarySelection` 这个 state 早就存在，只是从来没有渲染过复选框）。行里塞了 8 个字段、两个图标、一个两行的标题块，扫的时候读不出重点。

重做四条：

1. **一行只讲一件事**：单字头像 + 标题（一行）+ 摘要（一行灰字），其余是次要列。标题不再让「这是一段用于生成会议纪要的完整内容…」这种导入文件名占据两行。
2. **勾选列名副其实**：表头是全选（部分选中显示中间态，用 `node.indeterminate`，因为它是 property 不是 attribute，React 渲染不出来），每行一个真实 checkbox，选中行整行染色。网格卡片上也有，切换视图不丢选择。
3. **选择是一个模式**：只要有选中，上方就出现批量条（归档 / 删除 / 取消选择），清空即退出。删除与归档都有二次确认，且文案写清后果——归档说"保留"，删除说"不可恢复"。
4. **归档是范围，不是删除**：`archived` 字段只改列表归属，会议、录音、逐字稿、纪要一个不动。归档页签是独立的 scope：`libraryFilter === 'archived' ? !meeting.archived : meeting.archived`，归档会议不会混进「最近」。

**行操作默认隐身**：归档/删除两个图标 `opacity: 0`，在 `:hover` / `:focus-within` / 已选中时才出现（`@media (hover:none)` 下常显，触屏没有 hover）。列表的用途是读会议，不是瞄图标。

**后端**：`archive-meetings`（`{ids, archived}`）与 `delete-meetings`（`{ids}`），都返回 `done` / `failed`——一条失败不会拖垮整批。批量删除会先停掉正在录的那一场，再逐条走原来的单条删除路径，所以音频与 realtime 目录照样清理干净。

**验证**：新增 `tests/library-batch.test.mjs` 七条（归档保留内容只改标记、部分失败不整批失败、批量删除只剩该剩的、空批次是 no-op，以及三条界面契约：勾选列与全选中间态、归档 scope 与已归档标签、卡片视图也有选择）。harness 渲染了浅色与深色两版对照图。
